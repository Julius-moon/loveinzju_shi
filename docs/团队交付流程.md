# 团队交付流程

官网收单和付款核验统一由订单负责人管理。组员只接收已经确认可制作的需求，不要自行复制收款入口和收款账单。

1. 负责人核实真实到账、定制边界及档期，给订单分配唯一制作人。特殊素材先确认可承接和报价。
2. 制作人在本地创建 `orders/订单编号/`，复制对应 JSON 示例为 `order.json`，把客户素材放在同一目录内。仅使用订单授权提供的内容。
3. 按 `docs/产品与字段.md` 填写数据。文本里的换行写成 `\n`。不要向示例配置覆盖真实客户信息。
4. 运行 `python tools/build_gift.py orders/订单编号/order.json`。工具输出永久写入内容的单文件 HTML 和交付 ZIP。
5. 制作人检查，再由另一位组员复核。检查称呼、日期、正文、隐藏文字和落款；逐个点开照片/地点/信封，唱片需实际点击播放；生日等待并点击许愿。
6. 刷新或重新打开成品，确认定制内容仍存在。断网打开，确认图片、音频正常；至少用桌面浏览器和手机视口查看。单文件在微信里的打开能力受客户端限制，交付时附上打开说明。
7. 负责人私下邮件交付 ZIP，记录交付状态和客户勘误。客户点击“已付款，提交核验”后，团队需在24小时内联系确认交付安排；后台状态按实际制作/交付情况更新，付款声明仍需核对真实到账。

维护一份内部派单表即可，字段为订单编号、产品、制作人、承诺档期、状态、复核人、交付时间。姓名、邮箱、照片不用在多份表格里重复扩散。

公共模板改动才提交 GitHub。推荐分支名 `feature/record-polish`；避免使用含客户名字/邮箱的分支名。未经负责人确认，不覆盖官网，不把客户成品公开托管。
